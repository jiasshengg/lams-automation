# iRAT inspection and updates

Read [shared operating rules](../lams-tbl-authoring/references/shared.md) and the iRAT fields in [configuration](../lams-tbl-authoring/references/configuration.md).

Use `destinationFolderPath` and `lessonTitle` for the existing lesson. Resolve the exact activity, Team Setup, gate, and question titles. Inspect existing question rows when needed:

```bash
node scripts/run.mjs inspect:irat-questions --config configs/local.json --node '<IRAT_NODE>' --request-json '<REQUEST_JSON>'
```

`--source` inspects the configured source lesson instead. `--dump-question '<EXACT_QUESTION_TITLE>'` provides additional read-only question-editor evidence. Do not infer a correct answer from an existing answer key when the user says that key is wrong; use supplied corrected content or reviewed source evidence.

**Before transcribing any question from a Source-of-Truth docx, check that its correct answer is explicitly marked** (a uniformly bold/highlighted whole option, an `Answer:` / `Correct answer:` / `Explanation -` line, or an equivalent explicit key) — see [configuration](../lams-tbl-authoring/references/configuration.md). Never fill in a plausible-looking answer from outside knowledge when the source is silent. A question with no explicit marker gets flagged to the user by exact title/position/text and left out of the request until they answer; it is never authored with a guessed weight.

**A shared case/image spanning several adjacent questions is not always announced by the literal "Qxx-yy relate to this case" text** — the automated detector only catches that one exact wording; any other phrasing ("refer to this description and image below for questions 28 and 29", a heading with no question numbers, or no heading at all) must be recognized by hand from what the questions themselves depend on to make sense (see [configuration](../lams-tbl-authoring/references/configuration.md) for the full test). Check this on every run, numbered or not.

**Check every image for a caption by hand — automatic detection only catches a few conventional phrasings** (a Word Caption style, a "Figure/Table/…" prefix, or a link) and silently reports `caption: ''` for anything else, including a plain photo credit like "Medical gallery of Blausen Medical 2014". Read the line right after each image yourself and pass it as that image's `caption` when it's there; see [configuration](../lams-tbl-authoring/references/configuration.md) for why an explicit caption is now safe to supply even when the image is also picked up automatically.

**Two adjacent questions can share one image in two different ways that look similar but need opposite handling** — a shared case narrative (duplicate the image onto every question in the group) versus a bare "below"/"above" pointer pair with no narrative at all (the image belongs once, to the earlier question only; giving the later question `"images": []` is the only way to suppress an automatic duplicate). Getting this backwards either drops a needed image or shows the same figure twice in a row. See [configuration](../lams-tbl-authoring/references/configuration.md) for the full test, and always flag which pattern applies to the user rather than picking silently.

## Match the adapter's actual scope

The current `apply:irat` command requires a complete `irat` object and a complete inventory of the intended questions. It updates existing questions as new versions and creates missing multiple-choice questions through Create question → Multiple choice → Save, including an initially empty activity. When the user explicitly authorizes removal, `deleteQuestionTitles` may name exact existing question references to remove through the row's Delete action and verified confirmation dialog before the remaining questions are written. Duplicate titles, unauthorized unexpected questions, ambiguous deletion targets, and type mismatches stop before writes. It also updates the gate, Team Setup association, and advanced settings. It is not a minimal single-question patch endpoint.

Direct Question Bank management is read/import only. The automation may read Question Bank metadata/details and import an exact verified existing version into iRAT/tRAT, but it must never use a Question Bank edit or delete control or endpoint. Requested iRAT authoring still uses the activity's **Save as new version** path, which preserves the previous shared version instead of overwriting it. `deleteQuestionTitles` removes only exact activity references after the observed activity-level warning; it never authorizes deletion from the Question Bank.

For a targeted correction, preserve unrelated values from reliable current evidence or a current reviewed full request; never fill them from arbitrary example/default data. Only use the bulk adapter when its complete write scope fits the user's request. If that cannot be established, explain the specific missing data or that a narrower adapter is needed; do not claim this skill adds unsupported patching capability.

Question titles default to `Question N` (from `sourceQuestionNumber` or position); do not invent other titles. Fonts and sizes are never set — every field stays at the LAMS default and the adapter verifies that after each write. Supply `irat.sourceDocx` so italics, bold, underline, and sub/superscript are copied from the SoT document onto the request text; review any `SoT formatting warning` it prints. Optional per-question `feedback` writes a supplied rationale to general feedback; omission preserves existing feedback. Optional `prefixAnswersWithLetters` controls answer-letter prefixes. Basic inline HTML (`sub`, `sup`, `strong`, `b`, `em`, `i`, `u`, `br`) is retained in content, answers, and feedback; attributes and other tags are removed. DOCX text/rationale parsing is still manual/reviewed; `sourceDocx` imports associated images only. Missing questions append in request order; this operation does not reorder existing questions. Never infer an action from the SoT or from an inventory difference. When inspection finds an extra existing row that is neither requested nor already covered by explicit instructions, report every exact live title and stop before all writes. Ask for a separate instruction for each title: keep it completely untouched; update it while leaving the title unchanged; update it and change the title to an exact supplied value; delete it; or follow another exact instruction. Do not treat silence as permission to preserve, edit, rename, or delete. Only `deleteQuestionTitles` and exact-title versioned updates are currently implemented; if the user chooses untouched preservation, direct rename, or another unsupported action, explain that limitation and do not substitute deletion plus recreation unless the user explicitly chooses that fallback. An already-absent authorized deletion title is treated as an idempotent no-op.

Only multiple-choice questions and `displayAllQuestions=true` are supported by the live adapter. Correct answer weights must total 100; incorrect answers have zero weight. Preflight can reject an incorrect Team Setup association before the association-writing step, so this is not a general repair path for missing grouping or broken graph structure.

```bash
node scripts/run.mjs prepare:irat --config configs/local.json --request-json '<REQUEST_JSON>'
node scripts/run.mjs apply:irat --config configs/local.json --request-json '<REQUEST_JSON>'
```

`prepare:irat` is an optional read-only graph preflight. `apply:irat` saves by default and has its own preflight; append `--dry-run` for an inspection-only preview. Do not run the combined copy workflow for an existing lesson.

Saving an iRAT question as a new version, or saving the iRAT activity, can raise a prompt asking whether to apply the same changes to the matching tRAT. Always confirm every such prompt; never cancel or dismiss it. The adapter attaches the affirmative handler to every question save and to the final activity save, and reports every confirmed prompt message. It then opens the tRAT immediately, without a synchronization waiting period. For every exact same-titled question, it compares the selected version with the current iRAT version and, when they differ, selects the exact iRAT current-version UID in tRAT; it never assumes the last version-menu item is the correct one. It verifies the tRAT has the exact question inventory/order, no stale-version warnings, and matching Print View text, answers, SoT inline formatting, and images. It then restores the matching tRAT's advanced settings to their LAMS defaults, enables **Show confidence levels from** as the only deliberate override, selects the exact iRAT source, saves, reopens, and verifies the questions and settings again. Report the affected questions/settings, both Print View comparisons, confirmed sync prompts, and post-save checks actually performed. On failure, report any phases already saved and diagnostics; the workflow is not transactional. Route structural mismatches to [authoring validation](../lams-authoring-validation/SKILL.md) and rotation-only fixes to [gate settings](../lams-gate-settings/SKILL.md).

When LAMS confirms the sync prompt but omits newly created iRAT questions from tRAT, the adapter may import only the missing suffix through tRAT's observed Question Bank panel. Existing tRAT rows must already be the exact requested prefix, and every imported question must match the exact title, content, family UID, and current version UID verified from the lesson's iRAT. If an image-bearing current version is absent from search results, the adapter may load only that verified current UID directly and reverify its title/content before import. Extra, reordered, or ambiguous rows stop without automatic deletion or replacement.

Committed runs keep an ignored recovery checkpoint containing the exact lesson/request hash and each successfully saved immutable question-version UID. A retry may skip a question only when a fresh batched live snapshot still selects that exact UID and the resolved per-question request hash is unchanged. Any conflict stops rather than creating another version. Once the iRAT design save is checkpointed, a retry resumes at tRAT reconciliation instead of rewriting iRAT questions. Successful completion archives the checkpoint under ignored `artifacts/`.
