# Shared LAMS operating rules

Read repository `AGENTS.md`. Run commands from the repository root containing `package.json`, `configs/example.json`, and `src/`. These skills orchestrate the reusable Playwright/TypeScript scripts; they do not expand the scripts' capabilities.

- Keep stable URL/browser/selectors and fallback defaults in ignored `configs/local.json`. Pass changing values in shell-quoted `--request-json`; `workspaceCourse` is allowed per run, but `baseUrl`, `browser`, and `selectors` are not. See [configuration](configuration.md) for fields. Never store credentials or browser profiles in tracked files. Reuse the same resolved `browser.userDataDir` for setup, login, and all later runs on that computer; never substitute a temporary, incognito, generated, or copied profile when persistent authentication is expected, and never move an authenticated profile to another computer.
- The course is configurable with no playground allowlist. Navigation selects it; the global Authoring library may expose other folders. Resolve the intended lesson and destination before writing. Reuse established authorization without another approval turn; do not broaden a targeted request into unrelated edits.
- `--sot-docx`, `--ae-json`, and `--config` accept paths, filenames, and case-insensitive partial names. Lookup searches the working directory, Documents, Downloads, and Desktop, skipping hidden/generated directories and symlink entries. Exact names take priority. If multiple candidates remain, present them and accept a number or distinguishing name, then pass the selected path. Do not demand a full path for a unique match. Output paths are literal.
- Copy, rename, gate-fix, `apply:irat`, and `run:tbl-irat` save by default. No automatic preliminary dry run is required. `--dry-run` requests a preview; `milestone1` always previews. The combined workflow's dry run stops after the copy preview. `--commit` remains accepted for compatibility. Inspection/preparation commands are read-only. Learner-facing `lesson:index` is separate and still requires `--commit`; never append publishing to a request that only asks for authoring. A request for the full or end-to-end flow, or to deploy/publish/ready the lesson for the cohort, does include it. It is the stage run after AE, on explicit request only, and `--expect-design` should carry the title the authoring run saved so a different recently used design cannot be published by mistake. `lessonIndex.endDate` is lesson-specific and belongs in `--request-json`, never in `configs/local.json`.
- Shared navigation chooses the first visible match. Missing controls, content-specific ambiguity, and failed expected states can still stop execution. Use real DOM evidence and manual authentication; do not bypass prompts.
- Report exact targets, changes, verification evidence, mismatches, and diagnostics directories. A completed click is not proof of success. Multi-stage writes can leave partial saved results; inspect that state before retrying.
- Treat the Question Bank management surface as read/import only. Automation may read metadata/details and import one exact verified existing version into an activity, but must never use a Question Bank edit/delete control or endpoint. Requested iRAT authoring may still use the activity's **Save as new version** path, which preserves the previous shared version. An authorized iRAT/tRAT row deletion removes only the activity reference and is allowed only when the observed UI proves that scope.
- AE Assessment/gate creation, reviewed linear transition creation, exact gate-bypass transition removal, exact misconfigured planned-gate replacement, AE question writing, and SOT image import are supported. An iRAT run that discovers extra existing question rows reports every exact title and stops before all writes. Ask the user for a per-title decision—keep untouched, update without renaming, update with an exact new title, delete, or another exact instruction—and never infer the action. A later run may delete only exact question references explicitly authorized through `deleteQuestionTitles`; exact-title versioned updates are supported, while untouched preservation and direct renaming are not yet implemented and must not be silently replaced with deletion/recreation. Inferred, ambiguous, and AE question deletion remain unsupported. Run `npm run build` and `npm test` after code changes; documentation-only updates require skill/link validation rather than live LAMS runs.

For first-time setup or missing Node/npm/esbuild/Chromium, follow [first-time setup](../../../docs/first-time-setup.md). Use the official Node installer if Node is absent; do not assume Homebrew exists. Run `npm run setup` for a fresh local dependency install and user-completed LAMS sign-in, `npm run doctor` to diagnose without reinstalling or opening LAMS, or `npm run login:lams` to repeat only sign-in. When Microsoft offers **Stay signed in?** or an equivalent persistence choice, instruct the user to choose **Yes** if organisational policy permits, but never answer authentication prompts for them. Verify the authenticated LAMS course-menu control, close the Playwright context gracefully so the profile is flushed, and verify on a second launch that LAMS opens without another sign-in before declaring persistence successful. Never force-kill the login browser. If the second launch requires authentication, keep using the same profile and report the likely Microsoft or organisational session-policy limitation rather than copying cookies or profiles. Do not declare readiness from node_modules presence, executable existence, or a TypeScript build alone. Report runtime and login verification separately. Never request or handle credentials, automatically remove quarantine flags, or disable OS protections.

When a copy destination is omitted, save in the resolved source lesson folder without asking for destination confirmation. Copy commands derive `destinationFolderPath` and its display label from `sourceFolderPath`, overriding stale destination defaults in local configuration. An explicit per-run `destinationFolderPath` wins. Folder creation/rename still requires its requested target path. Existing-lesson edits and renames save in place; their destination fields identify the existing lesson rather than move it.

## Reliable execution and progress

Prefer `node scripts/run.mjs <operation> --request-json '<REQUEST_FILE>' --log-file '<LOG_PATH>'` for LAMS operations. It bypasses npm argument forwarding, rejects stray positional arguments, streams output, and preserves the child exit status. JSON files avoid shell quoting differences. Run from the repository root. Do not wrap commands in `| tee`, `| tail`, or a trailing successful `echo` when deciding whether they passed. Background runs are allowed; await their actual completion before starting another run on the same profile. A profile-lock error means wait for the owner, not delete browser lock/session files or launch a different profile.

Use `node scripts/run.mjs login:check` for unattended authentication verification. Never ask the user to sign in during that check; a failed check is followed by the separate interactive `login:lams` command. Do not claim an immediate pass establishes a days/weeks session lifetime or proves another computer is fixed.

Collect missing target, content-disposition, and publishing information together when possible. Continue independent authorized work while awaiting publishing details. Apply documented defaults without reconfirming them. After a technical failure, inspect diagnostics and partial saved state and resume the correct stage; do not ask permission merely to retry a verified safe action.
